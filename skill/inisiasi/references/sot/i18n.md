# Internationalization

> Last verified: 2026-11-16

Scope: i18n libraries per stack and formatting rules.

## Defaults

| Stack | Use |
|-------|-----|
| Next.js App Router | next-intl |
| Vite / TanStack / Svelte / Solid | Paraglide JS (typed, tree-shakable) |
| Nuxt | @nuxtjs/i18n |
| Vue | vue-i18n |
| Expo | i18next + expo-localization |
| Inline strings in the fbt style | fbtee |
| Go | nicksnyder/go-i18n |
| Python | Babel / gettext |
| Laravel | Built-in localization (`lang/`, `__()`) |
| Spring | `MessageSource`. Plurals need an ICU4J-based message source from a third-party library |
| Rails | Rails I18n (YAML), `i18n-tasks` for missing keys |
| .NET | `IStringLocalizer` with `.resx` files |

## Rules

- Every user-facing string lives in a catalog. Do not concatenate strings; use ICU plurals.
- Format dates, numbers, and currencies with `Intl.*`.
- Locale detection: saved preference, then device language, then a fallback.
- Public multilingual web: `/en/...` paths, `hreflang`, canonical URLs.
- RTL: use logical properties.
- CI checks for missing keys. Test with long text (pseudolocalization).
- A TMS if you have translators: Tolgee (open source), Crowdin, Lokalise, Weblate.
